# Gate 0 — USB 브리지 처리량 (USB-bridge throughput)

> d1-5 측정 결과, d1-6 결정 (Measurements for d1-5, decision for d1-6)
>
> - 펌웨어 (Firmware): `apps/bridge_test` — uart20 (P1.09 → SAMD11 → USB), UART async + EasyDMA, HFXO 요청
> - 프레임 (Frame): 257 B (header 15 + payload 240 + CRC 2), type 0x7F
> - 단계 (Steps): 10, 20, 30, 40, 60, 80, 100 kB/s, 최대 — 각 10초 / 10 s each
> - PC: `host/bridge_test.py --port /dev/cu.usbmodem03E4434C3 --baud <baud> --append notes/gate0.md`
> - 이론 한계 (Theoretical UART limit, 8N1): 115200 → 11.5 kB/s, 460800 → 46.1 kB/s, 1000000 → 100 kB/s

## 결정 규칙 (Decision rule, roadmap v4)
- 손실 없이 ≥ 30 kB/s → 마이크 **8 kHz** (기본안)
- 15–30 kB/s → **4 kHz**
- ≥ 90 kB/s → (선택) 32 kHz 원본 짧은 시험 추가

## 결정 (Decision)
- **마이크 레이트 = 8 kHz, UART baud = 1 000 000** (2026-11-10)
- 근거 (Rationale): 1 Mbaud에서 **98.8 kB/s까지 손실 0, CRC 오류 0** (각 단계 10초, 단계 9개). 필요량은 PPG 0.6 + 마이크 16 kB/s + 오버헤드 ≈ 20 kB/s → 용량의 약 20%만 사용.
  At 1 Mbaud, 98.8 kB/s with zero loss and zero CRC errors; the 8 kHz plan needs ≈ 20 kB/s (~20 % of capacity).
- ≥ 90 kB/s 조건 충족 → (선택) 32 kHz 원본 짧은 시험 가능: 64 kB/s + PPG + 오버헤드 ≈ 75 kB/s (용량의 약 76%, 여유 적음 → 짧은 시험만).
- SAMD11 브리지는 **PC가 연 baud를 그대로 따름** (115200 펌웨어는 115200으로 열 때만 프레임 수신) → PC와 펌웨어 baud를 항상 일치.
  The SAMD11 bridge uses the baud the PC opens the port with.
- 실측 한계 ≈ 이론값의 99% (115200 → 11.5, 460800 → 45.5, 1M → 98.8 kB/s) → 병목은 USB 브리지가 아니라 UART baud.
- 아직 확인 안 한 것 (Not yet checked): 10분 연속(Day 6), 센서 동작 중 CPU 부하 상태(Day 4). 원본 바이트: `data/raw/gate0_*.bin`
